# 实训学时合规与冻结服务

该服务汇聚学员签到、导师确认和请假修正事件，按培养方案与时区重放学时状态，并保存可追溯的学期冻结快照。项目还提供导师分配、证明材料、豁免复核、规则版本、名额、通知和数据留存等领域模块，供后续业务扩展时复用统一的状态与审计约束。

## 运行方式

默认数据保存在项目目录的 SQLite 文件中。安装依赖后执行 `uvicorn app.main:app --host 127.0.0.1 --port 8000`，健康检查地址为 `/health`，业务接口位于 `/api`。

## 测试

```bash
python3 -m pytest -q
```

## 学院数据质量评分

服务另提供校级学院数据质量评分，用于横向比较各学院上报事件的**及时性、重复率、冲突率**。设计上复用事件溯源与不可变冻结约束：

- **指标定义与规则版本**：`timeliness`（及时上报率，越高越好）、`duplicate_rate`（重复上报率，越低越好）、`conflict_rate`（同内容指纹被报成不同类别的冲突率，越低越好）。口径参数（上报时限、最小样本量、权重）固化在规则版本中；规则版本一经发布不可修改，口径变化只能发布新版本。
- **计算批次固定三要素**：观察窗口（按配置时区锚定本地午夜的半开区间 `[start, end)`，跨时区含 DST）、输入游标（纳入的最大 `report_id`）、规则版本。历史批次结果不可重算。
- **分项证据与置信标记**：每个学院输出三项指标的原始值、0–100 分项得分、加权综合分，以及逐事件证据（迟到清单、重复组、冲突组）；样本量低于 `min_sample` 时该指标及综合分标记为低置信。
- **迟到数据形成修订版**：游标之后到达的数据不影响历史批次，只能以 `revision_of` 指向旧批次创建修订版；修订版沿用父批次的窗口、时区与规则版本，仅推进游标。
- **申诉只调整经核实的来源**：申诉须针对已签发评分卡；核实通过后，仅对明确剔除（误报）或更正类别（误分类）的来源记录重算相关指标，形成修订批次，**不回写历史排名**。
- **签发不可变**：批次计算完成后可签发评分卡（含确定性排名与内容指纹）；并发签发同一批次仅一个成功。

### 评分接口（均位于 `/api/scoring`）

| 分组 | 接口 |
| --- | --- |
| 配置 | `POST /rule-versions/{version}`、`POST /rule-versions/{version}/publish`、`GET /rule-versions` |
| 输入 | `POST /incidents` |
| 计算 | `POST /batches/{batch_id}`、`GET /batches`、`GET /batches/{batch_id}` |
| 签发 | `POST /batches/{batch_id}/issue` |
| 申诉 | `POST /appeals`、`GET /appeals`、`GET /appeals/{appeal_id}`、`POST /appeals/{appeal_id}/resolve` |
| 趋势 | `GET /colleges/{college_id}/trend?metric_code=...` |

评分相关测试覆盖跨时区（纽约 DST 回退）窗口、并发签发、空样本窗口、崩溃后的重启恢复、迟到数据修订版以及申诉只改经核实来源等场景。
